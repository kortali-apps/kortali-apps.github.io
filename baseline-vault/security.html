Security – Baseline Vault for Jira

How the app protects your data. Last updated: 2026-11-14.

Topic Answer
Hosting Atlassian Forge only (functions, Custom UI, Key-Value Store). No vendor servers, no third-party services.
Data egress None. The app calls only Jira REST APIs through Forge (requestJira) and Atlassian's personal data reporting API (privacy.reportPersonalData). No fetch to external hosts, no analytics.
Runs on Atlassian Eligible: forge eligibility confirmed it for production version 3.0.0 on 2026-11-14.
Scopes read:jira-work, read:jira-user, storage:app, report:personal-data (only for the weekly personal data report). No write scopes on Jira data.
Authorisation Jira reads use asUser() so users see only what Jira allows them. Creating, editing and deleting requirement sets and deleting baselines require project admin (checked server-side with Jira's mypermissions API).
Input validation All resolver inputs validated server-side: IDs (UUID format), lengths, list sizes, field-ID pattern; JQL is scoped to the current project by numeric project ID and validated by Jira before saving.
Data stored Requirement set settings; baseline metadata (name, note, timestamps, creator account ID); baseline records (issue fields chosen by admins). Stored in Forge KVS for the customer's site.
Personal data Only the creator's Atlassian account ID. No names, emails or avatars stored (names are looked up when shown). User fields (assignee, reporter, user pickers) are never offered or recorded; @mentions are stored as "@user". A weekly scheduled trigger reports stored account IDs to Atlassian's personal data reporting API; closed accounts are erased from every baseline.
Integrity Each baseline has a chained SHA-256 fingerprint over its stored chunks; a verify function recomputes it. Finalised baselines cannot be modified through the app.
Encryption At rest and in transit by the Atlassian platform.
Data residency Follows the host site (Forge storage).
Retention / deletion Admin deletion in the app; on uninstall Atlassian deletes app storage per Forge rules.
Output safety CSV exports neutralise spreadsheet formulas (cells starting with = + - @ are prefixed); HTML reports escape every value and contain no scripts or external resources. UI is React with no dangerouslySetInnerHTML.
Dependencies Backend: @forge/api, @forge/resolver, @forge/kvs. UI: React 18, @forge/bridge. Built with Vite. Reviewed before each release.
Testing 11 automated tests (fake Jira and storage): paging, chunking, fingerprint and tamper detection, permissions, license, input validation, personal data handling. End-to-end test on a real Jira Cloud site on 2026-11-14.
Logging No personal data written to logs by the app.
Vulnerability reporting hello@provecore.com. Acknowledge within 2 business days.
Incident response Notify Atlassian within 48 hours of a confirmed security incident (Marketplace Partner Agreement), then affected customers.
Support SLA Critical issues identified by Atlassian: response within 24 hours; other requests within 5 business days.
