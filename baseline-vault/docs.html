Baseline Vault – user guide

Where to find it

Open a Jira project and choose Baselines & Traceability in the project sidebar.

1. Define a requirement set (project administrators)

A requirement set tells the app which issues are requirements and how to read their links.

  • Name: for example "System requirements".
  • Which issues are requirements: JQL applied inside this project, for example issuetype = Requirement. Leave empty to include every issue in the project. Any ORDER BY is ignored; results are ordered by key.
  • Test issue types: issues of these types verify a requirement (for example Test).
  • Implementation issue types: for example Story and Task.
  • Defect issue types: for example Bug. A defect counts as open until its status category is Done.
  • Link types to follow: leave all unselected to follow every link type.
  • Extra fields to record in baselines: up to 30 fields, custom fields included. Summary, description, status, priority, issue type and links are always recorded. Fields that hold people (assignee, reporter, user pickers) are not offered, so baselines never store personal data; @mentions in descriptions are recorded as "@user".

2. Traceability matrix

Choose Analyze traceability. The app reads the requirements with your own Jira permissions and shows: coverage by tests, tests done, implementation items and open defects for each requirement. Use the filters to list gaps, then Export CSV or Export report (a printable HTML file; print it to PDF). Nothing is stored by this view.

3. Baselines

Choose Baselines › Create baseline, give it a name and an optional note, and confirm. The app stores the current content of every requirement in the set. Baselines cannot be edited.

Fingerprint and verification. Every baseline gets a SHA-256 fingerprint computed over its stored content in order. Verify recomputes it and confirms the baseline is unchanged since it was saved.

View and export. View lists the stored requirements, including the description as it was at the time, and exports CSV or a printable report with the baseline details and fingerprint.

Who can do what: anyone who can open the project page can view, export, verify and create baselines. Only project administrators can edit or delete requirement sets and delete baselines.

4. Compare

Choose From (a baseline) and To (another baseline or the current Jira data), then Compare. You get added, removed and changed requirements; for each change the old and new values, with word-level highlights for descriptions and long text fields. Export CSV (one row per change) or a printable report.

Limits

  • Descriptions and long text fields are stored up to 20,000 characters each (longer text is marked as truncated).
  • Up to 30 extra fields per requirement set. Large sets are read 100 issues at a time, with a progress bar.
  • Baselines include only issues the creating user is allowed to see in Jira.

Data and security

All data stays in your Atlassian site (Forge storage). The app makes no calls outside Atlassian, uses no cookies, tracking or analytics, and reads Jira only with the permissions of the person using it. The only personal data stored is the account ID of each baseline's creator; the name is looked up when shown. If that account is closed, the app erases the ID and the baseline shows "Former user". See the privacy policy and the security answers for details.

Uninstalling

Uninstalling removes the app. Its stored baselines and requirement sets are held in Atlassian's Forge storage for your site and are deleted by Atlassian according to the Forge platform's data retention rules. Export anything you need first.
